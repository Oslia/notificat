# 天気データ連携

## 採用サービス

初期実装では [Open-Meteo Forecast API](https://open-meteo.com/en/docs) を使用する。API キーなしで HTTPS から取得でき、日本の座標では JMA MSM/GSM を含む適切な予報モデルが自動選択される。

無料 API は非商用利用向けで、上限は 1 日 10,000 リクエストである。稼働保証はなく、商用製品では有料 Customer API の契約が必要になるため、ポートフォリオ／開発段階の提供元として採用する。条件変更時に差し替えられるよう、アプリ本体は `WeatherProvider` インターフェースだけに依存する。詳細は [Pricing](https://open-meteo.com/en/pricing) と [Terms](https://open-meteo.com/en/terms) を確認する。

データは CC BY 4.0 で提供されるため、UI に `Weather data: Open-Meteo` を表示する。公開時の README や製品情報にも提供元へのリンクを記載する。

## 取得内容

エンドポイントは `https://api.open-meteo.com/v1/forecast` とし、設定済み地域の緯度・経度を渡す。

- `current`: 気温、体感温度、湿度、天気コード、風速
- `hourly`: 気温、天気コード、降水確率。現在から 24 時間を取得し、3 時間ごとの 8 件を保持
- `daily`: 天気コード、最高／最低気温、最大降水確率。当日から 7 日分を保持
- `timezone=auto`: 地域に対応するタイムゾーンと UTC オフセットを使用
- `timeformat=unixtime`: 組み込み側で軽量に時刻変換できる形式

WMO 天気コードはプロバイダーでアプリ共通の `WeatherCondition` に変換し、UI 側の `WeatherPresentation` で画像パスへ変換する。天気状態の名称は表示せず、アイコンを主表現とする。

画面表示には `rsc/weather/` の 100 x 100 PNG を使用する。`WeatherPresentation` が天気状態をファイルパスへ変換し、ホーム、現在値、3 時間間隔、7 日間の各 UI は同じ対応表を共有する。小さいカードでは LVGL の `CONTAIN` 表示で縮小し、サービス層は画像パスや LVGL に依存しない。

## 更新規則

1. Wi-Fi 接続済みで未取得なら直ちに取得する。
2. 取得成功後は 1 時間後に更新する。
3. 地域変更時は以前の地域の表示を消し、新しい地域を直ちに取得する。
4. Wi-Fi 切断中は通信せず、再接続時に取得を再開する。
5. API／通信エラー時は 5 分後に再試行する。取得済みデータは破棄せず表示を維持する。
6. 通信中の地域変更によって届いた古い応答は破棄する。

1 台あたり通常 24 リクエスト／日であり、無料枠に対して十分な余裕がある。ただし、多数の実機配布や商用化の前に利用条件と上限を再確認する。
