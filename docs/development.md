# Notificat 開発ガイド

## 目的

機能追加時に既存機能への影響を限定し、M5Stack CoreS3 のメモリ制約を守りながら保守できる構成を維持する。

## 依存方向

```text
ui -> features -> platform
        ^            |
        └─ core contracts ─┘
```

- `core/`: 機能に依存しないコンテキスト、システムイベント、起動調停。
- `platform/`: Wi-Fi、時刻、NVS など ESP-IDF とハードウェアに近い処理。
- `features/`: アラーム、天気、設定など、機能ごとの状態と UI。
- `ui/`: アプリ共通のシェル、テーマ、アプリライフサイクル。
- サービスから LVGL API を呼び出さない。
- UI から `Service::instance()` を呼び出さない。依存は `AppContext` から受け取る。
- 機能間で別機能の UI クラスを参照しない。共有状態はサービスまたはシステムイベントを介する。

## 新しいアプリ機能の追加手順

例として `Calendar` を追加する場合:

1. `main/features/calendar/` に状態モデルと `CalendarService` を作成する。
2. `main/features/calendar/ui/` に `CalendarApp` を作成し、`App` を継承する。
3. 必要なサービス参照を `AppContext` に追加する。
4. `AppManager` がアプリを静的に所有し、`AppRegistry::add()` を一度呼ぶ。
5. ソースファイルを `main/CMakeLists.txt` に追加する。
6. 要件と責務を `docs/requirements.md`、`docs/architecture.md` に追記する。

ランチャーは `AppRegistry` を列挙するため、`AppShell` へのボタン追加は不要である。アプリオブジェクトは静的に所有し、アプリ切替時は LVGL オブジェクトのみ破棄する。

## システムイベント

バックグラウンド処理から LVGL を直接操作しない。サービスは `SystemEventBus::publish()` で変更を通知し、`AppShell` が LVGL タイマー内でイベントを取得してアクティブなアプリへ渡す。

イベントはビットマスクとして併合される。同じイベントが短時間に複数回発生しても一回の更新として扱うため、通知回数ではなく最新スナップショットを正とする。

## スナップショットと並行処理

- UI はサービス内部データへのポインターを保持せず、スナップショットを値として取得する。
- ESP イベントやワーカータスクから更新するスナップショットは mutex で保護する。
- 大きな一覧と小さな接続状態は別スナップショットに分ける。
- イベントハンドラーのスタックに大きな配列を置かない。

## ネットワーク機能

天気取得は現在 `WeatherService` の専用ワーカーで実行する。ネットワーク機能を追加する段階で共通のネットワークワーカーへ移行し、TLS/HTTP リクエストを同時実行せず、キューで直列化して内部 RAM のピークを抑える。

データ提供元は `WeatherProvider` のようなインターフェースでサービスから分離する。実機用プロバイダーとテスト用プロバイダーを交換可能にする。

Open-Meteo のレスポンス本体は PSRAM に確保する。`CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y` により TLS の動的メモリも PSRAM に置き、LCD/SPI DMA 用の内部 RAM を残す。将来、認証情報を扱う API に変更する場合は、フラッシュ暗号化を有効にするか mbedTLS の内部 RAM 割り当てへ戻すかをセキュリティ要件と合わせて再評価する。

## 永続化

- NVS namespace と key は機能ごとに定数化する。
- 保存形式にはスキーマバージョンを持たせ、変更時に移行処理を追加する。
- Wi-Fi の「一時切断」と保存済み接続情報の「削除」は別コマンドとして扱う。
- アラームは `alarms` namespace の `schedule` blob に保存する。格納件数と時刻を読み込み時に検証し、不正なエントリを実行しない。

## アラーム

- `AlarmService` は UI 表示状態に依存せず、専用タスクで `TimeService` のローカル時刻を確認する。
- UI は `AlarmSnapshot` の値コピーを描画し、追加・変更・削除・有効化をサービスのコマンドとして渡す。
- 発火表示はアプリ固有画面ではなく `AppShell` のグローバルオーバーレイに置く。
- 音声出力は `AlarmOutput` の実装へ分離する。実機を使わないテストでは無音の fake output に交換する。
- 同一分の二重発火、時刻未同期、スヌーズ中の削除／無効化、スピーカー初期化失敗を確認する。

## 完了条件

- `idf.py build` が成功する。
- `git diff --check` で空白エラーがない。
- アプリを繰り返し切り替えてタイマーと LVGL オブジェクトが残らない。
- Wi-Fi 検索中、HTTP 通信中でも UI 操作が停止しない。
- 機能追加による内部 RAM と各タスクの最小スタック残量を確認する。
